# Рабочий архив Elias: что он даёт независимому движку

Проверено 24 октября 2026. Источник — переданный владельцу проекта архив [SLRR-REVERSE-WIP.zip](https://drive.google.com/file/d/1jBThp7EfOokCvFS4ku7k6HihiGmYl7XP/view?usp=drivesdk), SHA-256 `6bce17950474f4c1244b28efae0b1dbb99c35151094626e1eacd8c04730e5d8a`, размер 344 157 522 байта. Это снимок рабочей папки исследователя, **не исходники Invictus**. Файлы из архива не добавлены в Git: там есть игровые ресурсы, EXE, база IDA, результат сборки и промежуточные журналы. Все указанные ниже пути относятся к корню архива.

В переписке автор говорит, что начинал реверс с версии **2.2.1** и хотел сделать x64/DX11 host. Проверенный архив пока содержит x86/D3D9 host; точный номер версии его EXE по одной переписке и имени файла не устанавливается.

В архиве 12 601 запись: `game/` (9873), `sources/` (1593), `native/` (1101) и `docs/` (22). В `native/engine/` находится C++ host с собственными TUFA/TREE, RPAK, native-мостом, D3D9 и приближённой физикой; `native/docs/` хранит инвентарь, адреса и промежуточные отчёты; `game/StreetLegal_Redline.exe.i64` — база анализа IDA (~56 МБ). Самые поздние проверенные записи датированы 9 октября 2026 года. Публичный [EliasFD3S/slrr-reverse](https://github.com/EliasFD3S/slrr-reverse) публикует код host под MIT, но не игровые ресурсы и не содержимое этой рабочей папки.

## Проверенные в архиве опорные сведения

| Область | Свидетельство в архиве | Значение для TypeScript host |
|---|---|---|
| JVM/native ABI | `native/docs/abi_bridge.md`: автор документирует `JVM_RegisterNative` по адресу `0x00416B00`, native-вызов через `CallInfo*` и `JVM_UnboxArg`, четыре места регистрации; `native/docs/native_registry.json` содержит 360 записей. | Сопоставить наши native-контракты по `class + name + signature`; не считать ABI обычным JNI. Число зарегистрированных записей не равно числу полноценно реализованных функций. |
| Загрузка скриптов | `native/docs/abi_bridge.md`: `compileSource` ищет `{dir}/src/{name}.java` и `{dir}/{name}.class`, проверяет magic TUFA; `native/engine/core/Jvm/` содержит реализацию своего TREE host. | Полезно для порядка загрузки и покрытия опкодов нашего runtime. Это сторонняя реализация, а не доказательство совместимости произвольной JVM. |
| Колёса и подвеска | `native/docs/evidence/wheel_phys_host.json`, `native/engine/runtime/Parts/WheelRef.cpp`: автор восстановил таблицу колёс с шагом `0x2B4`, ссылками на arm/hub/opposite wheel; исходная ветвь выделяет дочерние физические тела hub и a-arm. | Проверять наши крепления и кинематику по исходным данным. Сам автор помечает выделение этих физических тел и полный wheel table в своём host как OOS: закон движения не восстановлен этим sidemap. |
| Повреждение колеса | `sources/parts/scripts/bodypart/SRC/Chassis.java` вызывает `getWheelDamage` при save и `setWheelDamage` при load. В `native/engine/runtime/Parts/Body/Chassis_part2.inc` приведён разбор функций `0x0043D080` / `0x0043D280`: активный флаг, формат десяти чисел, позиция/ориентация и дополнительные поля. | Для совместимого сохранения и сети wheel damage следует рассматривать отдельно от `Part.condition`. Наш source runtime сейчас переносит эту строку как непрозрачное значение; строгая реконструкция её семантики остаётся задачей. |
| Шаг физики | `native/engine/runtime/Resources/Resources_part4.inc` описывает исходный `Physics_Step` (`0x004A5190`), накопитель времени, списки тел и цикл solver до 20 итераций. | Даёт точки входа для дальнейшего реверса, но не уравнения ограничений и пластической деформации. |

**Граница достоверности.** Это утверждения исследователя, подкреплённые адресами и комментариями его реверса; в этой работе исходный EXE из архива независимо не дизассемблировался. `native/engine/runtime/Resources/Resources_part4.inc` прямо называет собственную интеграцию `Soft`: Euler + упрощённые столкновения, без исходных `sub_4A3900`, `sub_4A2D10`, `sub_4A2540` и constraint solver. Показатель `96.6%` в `native/docs/progress_global.json` — авторская взвешенная метрика задач на 9 октября, не измерение эквивалентности движка или физики. В документах архива есть промежуточные числа 360 и 372 для разных инвентарей native; перед использованием следует сверить конкретный реестр и метод подсчёта.

## Следующие точные проверки

1. Сопоставить функции из `native/docs/` с каждой локальной версией EXE по сигнатурам и вызовам, затем подтвердить смещения wheel table и основные ветви `Chassis.forceUpdate` на нужном бинарнике.
2. Проверить десятипольную строку wheel damage на контрольном сохранении: round-trip, порядок полей, нулевой флаг и влияние на позу колеса. В существующем runtime не заменять непрозрачный путь до подтверждения.
3. Исследовать исходные `Physics_Step` и вызванные constraint-функции в базе IDA, отделяя оригинальный алгоритм от `Soft`-замен C++ host. Только после этого решать, какие параметры можно переносить в нашу физику кузова и подвески.
4. Использовать native registry и smoke-журналы как карту пробелов для TypeScript host. Архитектурная цель остаётся браузерный WebGL-движок; C++ host полезен как независимый эталон исследования, а не обязательная зависимость.
