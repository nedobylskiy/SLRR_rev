# Main menu and OSD

The first OSD screen reads `sl/Scripts/game/src/MainMenu.java` from the connected SLRR installation. Its interpreter core now lives in the [SLRR-JVM package](../packages/slrr-jvm/README.md); the menu adapter supplies game-specific host calls. The limited interpreter executes `MainMenu.enter()`, its constructor, `Gates.show()`, `Gates.buildSlidingMenu()`, `Gates.osdCommand()`, `Gates.run()` one tick at a time, `ColorBank`, and `MainMenu.exit()`. The Java host currently receives an initial game state without a career or saved car. The source code determines the menu items, their conditions and commands, RPK resource links, sizes, initial selection, and the selected label's color animation. Arrow keys invoke `osdCommand()` and its built-in `SlidingMenu.execute()` adapter, which clamps selection at the ends of the list.

`OsdLayer` places elements in the original OSD's screen coordinates: center `(0, 0)`, corners `(-1, -1)` and `(1, 1)`, with Y pointing down. It uses a fixed 16:9 aspect ratio independently of the Three.js camera. It supports image rectangles, text, buttons, visibility-controlled groups, and disposal of loaded resources. Later Java-driven screens can build on this layer.

The main menu opens when the selected installation contains that Java source and `frontend.rpk`; it can be reopened with **Main menu**. The slider has finite ends. Arrow keys or on-screen buttons change selection, Enter activates an item, and Esc returns to the resource catalog. `FREERIDE` opens the current Test Track drive. Calls to `runAnimation()` and `teleport()` from `Gates.showPrimaryVisuals()` define the entrance of the bar, slider, and logos. On exit, `Gates.cleanup()` runs, including `reverseAnimation()`; `OsdMotionController` implements shared motion operations. Browser animation approximates the original steps at 16 ms per step. The background comes from `data/Fmv/background_motion_HD.avi`: the local server converts Cinepak to WebM and keeps the result in memory. If playback is unavailable, it displays the original `bck.png` from `frontend.rpk`. Game assets are not committed to the repository.

Calls from `Gates.show()` to adjacent systems (audio, video, loading screen, cursor, and other scripts) currently use narrow stubs. Rendering the frame, logos, arrows, and background movie remains a version-specific adapter. The first splash screen is skipped and `Gates.showPrimaryVisuals()` is called after login. Career, loading, and other menu commands do not yet execute their Java branches; `FREERIDE` is wired to the current drive separately. Testing an earlier release requires its `MainMenu.java` and resources, and may require interpreter or built-in OSD API extensions. The interpreter does not use JavaScript `eval` and rejects unsupported operations.


Text positioning keeps intrinsic glyph dimensions when Java `Text.setPos` supplies zero width/height. Explicit zero-sized native widgets retain their existing bounds behavior. This matters for Garage's `TIME: ` right-aligned title and left-aligned clock: both intentionally share one anchor, and a forced `0%` text width would make the right-alignment transform ineffective. Text preserves whitespace, including the authored trailing space between title and value. Original Java coordinates and alignment constants are unchanged.


`Text.getWidthPixels` returns metrics in Java's configured display-pixel units: canvas/CSS glyph widths are scaled by `Config.video_x / OSD stage width` when a browser stage is available. Original Java `Text.getWidth` then divides by `Config.video_x * viewport.getWidth`, yielding the normalized width of the actually rendered CSS glyphs. Without this conversion, `TextBox` manually centers long lines too far left whenever the configured game resolution differs from the browser OSD stage. No Java alignment/coordinates or user video settings are overwritten; hosts without Config/stage dimensions retain the previous metric fallback. Recreating a dialog recalculates its wrapping and line positions for the current stage size.


Browser-backed Text metric adapters also provide `getLineSpacing`, `getHeight` and `getCharWidth` against CSS stage dimensions and the requested viewport fraction. The original 1.25 line-spacing factor and font sizes are preserved. Java `TextBox` still creates/wraps its lines, but no longer spaces them using the unrelated configured video height, which could push long dialog content over the button and outside the background. Config values and dialog dimensions are unchanged. Non-browser hosts without a stage callback retain their original Java metric methods.
