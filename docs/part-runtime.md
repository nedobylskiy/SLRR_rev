# Part.save/load через память: сохранённый результат исследования

`src/runtime/java-source.ts` разбирает ограниченный поднабор Java и интерпретирует выбранные методы без `eval`, `Function` и доступа к ambient JS. `src/runtime/part-assembly.ts` реализует явные host-операции: экземпляры, слоты, ресурсы, примитивы File, повреждения и тюнинг. Выполняются **методы из локальных Java-исходников**, не TUFA этих методов. Общей JVM это пока не является.

`PartAssemblyRuntime.serialize(root)` вызывает виртуальный `save` через MemoryFile и выдаёт SDAT type 2 в Uint8Array. `restore(bytes, replace?)` вызывает оригинальный `Part.createFromFile` и виртуальные `load` в отдельном подготовленном мире. Только после полного чтения, проверки чисел и дерева он регистрируется, а replace уничтожается. При ошибке подготовленные объекты освобождаются, старый мир остаётся рабочим. Файлы автомобиля на диск не записываются.

`npm run verify:parts` читает семь оригинальных исходников: Part, BodyPart, Chassis, RGearPart, ReciprocatingRGearPart, Tyre, ShockAbsorber. Проверка создаёт **синтетическую** сборку из 10 деталей с явными определениями, выполняет реальные исходные save/load, сравнивает дерево и байты, делает 1000 восстановлений и проверяет неизменность счётчиков. Дополнительно проверяются rollback при позднем NaN, штатный clamp амортизатора и независимость восстановленной сборки. Для исследованного набора получается 1106 байт. Отчёт `local/parts-verification.json` включает SHA исходников и трассы методов; исходные тела в репозиторий не копируются.

Поддержаны super/виртуальные вызовы, локальные переменные, циклы и условия, арифметика, типизированные int/float и необходимые host-классы. Ограничены инструкции, глубина вызовов, число деталей и размер буфера. Неизвестные методы/грамматика завершаются ошибкой. Конструкторы произвольных игровых классов, массивы и полный Java frontend ещё не поддержаны. Host-значения для этого теста задаются явно; `forceUpdate` учитывается как вызов, физику не пересчитывает.

Это не универсальный декодер сохранений: подклассы с другими хвостами требуют исполнения своих исходников и host API. Это также не полный Vehicle v5 файл, не динамическое состояние гонки и не исправление утечки старого EXE. Счётчики проверяют владение данной модели, но не заменяют профилирование heap/GPU/physics.

Приоритет теперь — [единый мир движка](engine-world.md). Данный runtime и проверка сохраняются как подсистема совместимости; объединение с CFG-миром потребует явного адаптера вместо двух независимых моделей деталей.
