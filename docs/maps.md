# Карты: первый проход на Test Track

Исходный `sl/Scripts/game/src/TestTrack.java` выбирает `maps.test_track:0x00000001r`, то есть корень `maps/test_track.rpk`. В установленном пакете 344 записи: один корень типа 1, 170 mesh-записей типа 5, 169 render-записей типа 14 и несколько вспомогательных ресурсов. У render-корня `Test_track` ID `0x14`; он сам и 167 его дочерних render-записей ссылаются через свойство `mesh` на внешние модели. Отдельная запись `minimap` не входит в геометрию сцены.

Новый загрузчик проходит эти связи в RPK и открывает исходные SCX и текстуры из установки игры. Вершины участков уже содержат координаты карты в сантиметрах, поэтому на узел модели применяется общий масштаб `0.01`, без ручной расстановки объектов и поправок под конкретную машину. На локальном Test Track загружается 168 моделей и 67 021 треугольник. Сцена доступна кнопкой «Тестовый трек».

Пропущенная ранее окружная дорога — `palya.scx` (11 295 треугольников). В RDB ресурс `0x15` указывает на `palya.scx`, а собранный RPK указывает на одноимённый `palya.scY`: этот SCY содержит материалы без треугольников. Если рядом с SCY существует SCX, загрузчик берёт геометрию из него. Render-запись `0x14` имеет один нулевой терминатор после текстового RSD, который раньше ошибочно помечал всю запись бинарной. Оба исправления основаны на свойствах ресурсов, без списка имён моделей карты.

Для тестовой поездки SCX-треугольники индексируются по ячейкам 16 м. Вертикальная выборка даёт высоту и нормаль восходящей поверхности; на ней работают лучи четырёх колёс и контакт кузова. На локальной карте индексировано 48 467 таких треугольников. Ещё 20 538 боковых треугольников индексированы по ячейкам 8 м для двухстороннего контакта кузова с ограждениями и постройками. Старт `0, -1461.785` и направление `3.14` взяты из прямой 1/4 мили в `TestTrack.java`. Точка выхода `(-456, 0, -584)` теперь тоже покрыта дорогой, но в демонстрации сохранён старт на прямой.

В бинарном содержимом корня `test_track.rpk` обнаружен блок RSD, но сигнатуры PHYS/POLY отсутствуют во всех его записях. Физическая модель сейчас получена **из исходной сетки SCX**, а не из отдельного оригинального физического слоя. Она поддерживает высоту дороги и контакты кузова с боковыми гранями; пока нет непрерывного обнаружения высокоскоростных столкновений, контакта колёс с вертикальными стенами, многоуровневой вертикальной выборки, объектов из бинарных блоков и игровой логики заезда. За пределами извлечённой поверхности нет невидимой плоскости. Различия между визуальной и игровой коллизией, включая деревянную рампу, исследуются отдельно в [разборе физики карт](map-physics-investigation.md).

Выбор дочерних render-ресурсов сделан через типы и `superId`, а не по именам `area_*` или списку файлов Test Track. Такой же проход подходит другим картам с этой схемой RPK, если их SCX поддерживаются текущим парсером.

Отдельные объекты трассы — деревья, фонари, знаки и контейнеры — описаны в исходном `maps/test_track.rdb` как экземпляры `typeof 1` с `gametype` и шестью координатами `params`. В собранном RPK эти экземпляры отсутствуют, поэтому загрузчик теперь читает доступный RDB, разрешает `gametype` через таблицу зависимостей RPK, читает скомпилированный `ICFG` объекта и использует его `render`/`body`. На локальном Test Track так разрешаются 1413 экземпляров 11 типов, в том числе 80 контейнеров. Повторяющиеся модели рисуются через `InstancedMesh`; формы `body ... box` дают ориентированные статические контакты кузова и опору колёс на верхней поверхности. Луч проверяет повёрнутую CFG-коробку в её системе координат; нижняя сторона не становится дорожным покрытием. Это восстановление по текстовому источнику карты, совпадение версии RDB с RPK ещё нужно проверить на оригинальном EXE. Прочие формы CFG, кроме `box`, не перенесены.
