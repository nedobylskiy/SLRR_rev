# Карты: первый проход на Test Track

Исходный `sl/Scripts/game/src/TestTrack.java` выбирает `maps.test_track:0x00000001r`, то есть корень `maps/test_track.rpk`. В установленном пакете 344 записи: один корень типа 1, 170 mesh-записей типа 5, 169 render-записей типа 14 и несколько вспомогательных ресурсов. У render-корня `Test_track` ID `0x14`; 167 его дочерних render-записей ссылаются через свойство `mesh` на внешние SCX. Отдельная запись `minimap` не входит в геометрию сцены.

Новый загрузчик проходит эти связи в RPK и открывает исходные SCX и текстуры из установки игры. Вершины участков уже содержат координаты карты в сантиметрах, поэтому на узел модели применяется общий масштаб `0.01`, без ручной расстановки объектов и поправок под конкретную машину. На локальном Test Track загружается 167 моделей и 55 726 треугольников. Сцена доступна кнопкой «Тестовый трек».

Бинарное содержимое корневой записи карты, в том числе возможные блоки LOD/PHYS/POLY, пока не декодируется. Поэтому это **визуальный просмотр** карты: физическая поверхность дороги, столкновения, размещение объектов из бинарных блоков, старт автомобиля и логика заезда не реализованы. Точка выхода `(-456, 0, -584)` и маршруты заезда есть в `TestTrack.java`, но загрузчик их не использует для позиционирования модели.

Выбор дочерних render-ресурсов сделан через типы и `superId`, а не по именам `area_*` или списку файлов Test Track. Такой же проход подходит другим картам с этой схемой RPK, если их SCX поддерживаются текущим парсером.
