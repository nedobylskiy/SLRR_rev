# Дорожная карта и критерии приёмки

## 0. Основание — достигнуто частично

- Чтение оригинальных RPK, TUFA, SCX v3/v4, SDAT; отчёты и проверка корпуса — готово.
- WebGL-показ отдельных моделей и переход RPK→mesh — реализовано, нуждается в расширении визуальной проверки материалов.
- Первый оригинальный метод Object.equals — исполняется; общий runtime не готов.
- Буферная сериализация новой модели автомобиля — реализована; capture/restore живого мира отсутствует.

## 1. Мир движка — текущий приоритет

План до первого управляемого автомобиля и проверка имеющихся native-контрактов: [игровая функциональность](gameplay.md). Начат мост Part ↔ CFG-world: getSlots/getSlotID/partOnSlot/slotIDOnSlot работают на существующих экземплярах.

Сначала завершить RPK/CFG factory, suspension/bone/compound frames, единый lifecycle экземпляров и VM, затем коллизии и физику. Явная совместимость слотов и frames колёс/руля работают на пяти машинах; Baiern собирается из 33 объектов без пропущенных stockpart. Есть [пробная поездка](mounts-and-driving.md) с упрощённой кинематикой. Подробные критерии: [мир движка](engine-world.md). Мультиплеер и расширение отдельной демонстрации сериализации отложены до работающей основы.

## Состояние автомобиля в памяти — сохранённая подсистема

Ограниченный Java source runtime уже исполняет выбранные оригинальные Part.save/load через MemoryFile с транзакционным восстановлением, 1000 повторами и rollback. Это синтетическая сборка; TUFA этих методов и capture CFG-мира ещё не реализованы. [Подробности](part-runtime.md).

Определить host-модель Part/Chassis, стабильные ID и владение. Восстановить достаточную семантику TREE/File для вызова исходных Part.save/load на MemoryFile либо реализовать versioned adapters с тестами каждого класса. Сохранить RPK-remount и transient paint data. Не маршрутизировать network baseline через File.open на диске.

Готовность: реальная собранная машина нового мира → буфер → новая независимая машина; совпадают детали/слоты/состояния/повреждения/окраска; старая машина не меняется до успешного commit; error rollback освобождает всё выделенное. 1000 повторов с реальными native-ресурсами не наращивают счётчики/heap.

## 2. TUFA VM и native API

Поля и вызовы по descriptor, inheritance/static initialization, массивы, branching, arithmetic, native adapter. Сверить с маленькими исходниками и class, не переносить эвристические hacks внешней реконструкции. Исполнение в Worker с лимитами, ошибки с source info.

Готовность: исходные конструкторы деталей и их save/load исполняются; список missing natives воспроизводим; unknown op не пропускается. Затем минимальная загрузка GameLogic/гаража. Компилятор `.java` — самостоятельная задача, включая resource literals и int truthiness.

## 3. Ресурсы мира и сборка машины

CFG slot/attach, трансформы, render/texture overrides, collision shapes и native lifecycle. Полная иерархия RPK, embedded map chunks, карта со spawn и камерой.

Готовность: собрать автомобиль из chassis и деталей по штатным конфигам, разобрать/собрать без потерянных объектов; загрузить одну реальную трассу с коллизией. Пустой внешний SCX карты не считается успешной загрузкой.

## 4. Физика и gameplay

Приоритет уточнён: сначала [деформация и разрушаемые крепления одной детали](deformable-physics.md), затем общая динамика кузова/подвески. Выбор backend должен учитывать это требование; обычный монолитный rigid body автомобиля не является целевой архитектурой.

Первый [стенд оригинального капота](hood-prototype.md) реализован: пластичность, реакция/разрыв опор, узловой контакт с полом. Следующий интеграционный режим описан ниже; snapshots физического состояния и силы между деталями ещё предстоит реализовать.

[Капот на собранной машине](car-crash-demo.md) уже получает контакт с препятствием и отсоединяется через EngineWorld.detach; PartHost видит изменение топологии. Следующие интеграции — контакты с самим кузовом, динамическая отдача шасси, физические snapshots и затем остальные детали/подвеска.

Выбрать backend после калибровки единиц. Воспроизвести native tyre/suspension/engine/gearbox интерфейсы; минимальный input и driving loop; затем гараж/каталог/ремонт/тюнинг/карьера. Серверный прогон без рендера должен использовать тот же world model.

Готовность: управляемая машина, baseline сохраняет настроенный автомобиль; тесты ускорения/торможения/подвески/повреждений; исходные scripts не требуют скрытых заглушек.

## 5. Сетевая гонка

Авторитетный сервер, content handshake, inputs, dynamics, late join/reconnect, baseline revision и resync. После корректности — compact binary deltas и оптимизация.

Готовность: две независимые клиентские сессии и сервер, одинаковая сборка машины с разным load order, движение с коррекцией, повреждения и замена деталей, устойчивый reconnect. Сериализатор в unit-тесте не считается мультиплеером.

## Исследовательские блокеры

Точная точка утечки в старом EXE не установлена. Изученные EXE без PDB. Предполагаемый полный оригинальный исходник от сообщества не получен. Форматы embedded map geometry/physics и анимаций не разобраны. Полная семантика TREE и native API не восстановлена. Это текущие незакрытые работы, а не основания выдавать проект за готовую игру.
